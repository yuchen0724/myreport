# 自定义报表查询系统 - 开发路线图

## 总体规划

### 当前状态（2026-05-29 复盘）
- ✅ 用户认证和权限管理
- ✅ 数据源管理（PostgreSQL + Doris/Hive）
- ✅ SQL模板管理和版本控制
- ✅ 参数化查询和NL2SQL
- ✅ 异步导出（Excel/PDF）
- ✅ 模板分享功能
- ✅ 数据可视化（图表）
- ✅ 限流和缓存机制
- ✅ 一键启动脚本
- ✅ 销售预测、RCA 根因分析、AI 数据分析师、订阅推送、SQL 审核、连接池监控已进入主功能面

### 技术栈
- 前端：Vue 3.3.4 + Element Plus 2.4.2 + Pinia 2.1.7
- 后端：FastAPI + SQLAlchemy + PostgreSQL + Redis + Celery
- 部署：Docker Compose + Nginx

### 当前工程基线
- 前端 `npm run lint`、`npm run typecheck` 与 `npm run build` 已恢复通过，Element Plus 与 ECharts 已做按需/分块优化，生产构建已切到 Terser 压缩以让 `drop_console/drop_debugger` 生效。
- 后端核心回归已恢复，当前语义指标、订阅与查询链路相关回归为 `145 passed, 4 warnings`。
- Pydantic v2 `Config` 迁移 warning 和调度服务 `datetime.utcnow()` warning 已清理；剩余 warning 为 passlib/Python 3.12 依赖告警和本地默认安全配置提示。
- 已新增 `scripts/verify-local.sh` 本地验证脚本，固化前端 lint/typecheck/build 与后端核心回归门禁。
- 生产密钥占位符检查、`v-html` sanitizer、`live/ready` 健康检查已落地。
- 查询执行链路已拆分出数据源 engine 工厂、SQL 分页器和查询执行器。
- 语义指标 MVP 已具备模型、迁移、CRUD、SQL 预览、执行、版本记录、回滚、用户级共享权限、前端管理页、仪表盘绑定、NL2SQL prompt 接入、AI 分析师工具接入、RCA 绑定、订阅绑定、订阅前端入口和 owner/admin 基础权限。

## 技术债务清单

### 高优先级技术债务
1. 本地验证脚本已覆盖核心门禁；后续需要接入 CI、扩大 API 集成测试覆盖并解决少量 ASGI 用例超时问题
2. 指标权限当前支持 owner/admin 与用户级 viewer/editor，共享组、行级/列级权限尚未落地
3. 数据质量和报表 SLA 监控尚未落地
4. 本地测试仍会提示默认安全配置 warning，后续可通过测试环境显式注入安全变量收口

### 中优先级技术债务
1. 前端重依赖 chunk 偏大
2. 缺少统一语义指标层
3. 缺少数据权限控制
4. 缺少数据质量和报表 SLA 监控
5. 日志收集和健康检查需要完善

### 低优先级技术债务
1. 缺少多语言支持
2. 缺少个性化设置
3. 缺少快捷键支持
4. 依赖版本需要升级
5. 代码需要重构优化

## 风险评估

### 技术风险
1. **性能风险：** 大数据量查询可能导致性能问题
   - 缓解措施：实现查询结果缓存、优化数据库查询、添加分页

2. **安全风险：** SQL注入、数据泄露等安全问题
   - 缓解措施：加强输入验证、实现数据脱敏、添加审计日志

3. **稳定性风险：** 系统可能出现不稳定情况
   - 缓解措施：添加集成测试、完善错误处理、实现监控告警

### 业务风险
1. **用户体验风险：** 系统复杂度可能影响用户体验
   - 缓解措施：优化界面设计、添加操作引导、简化操作流程

2. **功能风险：** 新功能可能引入bug
   - 缓解措施：加强测试、灰度发布、快速回滚机制

### 资源风险
1. **开发资源风险：** 开发任务较多，可能资源不足
   - 缓解措施：按优先级排序、分阶段实施、合理分配资源

2. **运维资源风险：** 系统复杂度增加，运维压力增大
   - 缓解措施：完善监控告警、实现自动化运维、简化部署流程
